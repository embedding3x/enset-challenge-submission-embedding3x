# Kubernetes deployment (minikube)

Deploys the full Agentic TP Platform into a local minikube cluster:
Postgres (pgvector), single-node Kafka (KRaft), Eureka, the three Spring
services, the four LangGraph agents, the agent gateway and the frontend.
Ollama stays on the host Mac — the cluster reaches it through the `ollama`
Service/Endpoints created at deploy time.

## Prerequisites

- minikube (docker driver) + kubectl
- Ollama running on the host and listening on all interfaces:
  `OLLAMA_HOST=0.0.0.0 ollama serve`
- A root `.env` file (same one docker-compose uses)

## Deploy

```bash
./infra/k8s/deploy-minikube.sh          # builds 10 images inside minikube, applies manifests
kubectl -n agentic-tp get pods -w       # wait until everything is Ready
minikube tunnel                         # separate terminal — binds LoadBalancers to localhost
```

Then open http://localhost:3000. The frontend build expects the API gateway on
`localhost:8080` and the agent gateway on `localhost:8000`, which is exactly
what `minikube tunnel` provides via the three LoadBalancer services.

Re-deploy after a code change: `./infra/k8s/deploy-minikube.sh` again (rebuilds
images in place; bump or delete pods to pick them up:
`kubectl -n agentic-tp rollout restart deploy`).

Tear down: `./infra/k8s/deploy-minikube.sh down`

## Layout

| File | Contents |
|---|---|
| `postgres.yaml` | pgvector StatefulSet + PVC + init script (auth_db · tp_db · rag_db) |
| `kafka.yaml` | Single-node Kafka in KRaft mode, StatefulSet + PVC, `kafka:9092` |
| `discovery-server.yaml` | Eureka registry |
| `auth-service.yaml` / `tp-service.yaml` / `api-gateway.yaml` | Spring services |
| `agents.yaml` | explanation / hint / evaluation agents + orchestrator |
| `agent-gateway.yaml` | FastAPI gateway (Kafka producer, RAG) |
| `frontend.yaml` | Next.js app |

Configuration comes from the `platform-env` Secret, generated by the deploy
script from the root `.env` (plus a derived `RAG_DATABASE_URL`). Manifests
override service-to-service URLs with in-cluster DNS names.

## Design notes

- **Eureka in k8s** is redundant (k8s Services already do discovery) but the
  Spring Cloud Gateway routes through it; keeping it avoids touching gateway
  code. A follow-up could switch the gateway to `lb:=false` static URIs.
- **Kafka** is intentionally a 1-replica KRaft node with replication factor 1 —
  right-sized for a demo, not HA.
- **No resource requests/limits** are set so the heavy JVM pods schedule freely
  on a single-node minikube. Add requests before running on a shared cluster.
